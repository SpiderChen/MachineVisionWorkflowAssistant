# AutoPrintDeliveryOrder — 出货单自动打印助手

基于 **纯计算机视觉 + 系统级鼠标键盘事件** 的桌面自动化工具：
不依赖浏览器驱动（Selenium/Playwright）、不依赖目标程序的 DOM/控件句柄，
只看屏幕像素、只发真实的鼠标/键盘输入，因此对 **网页、C/S 客户端、远程桌面内的程序** 一律适用。

> 典型流程：收到触发（数据库变动 / 外部 API 调用）→ 检查目标页面状态 →
> （如在登录页则走自动登录）→ 输入车辆自编号 → 点击打印按钮 → 回报结果。

---

## 1. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                      托盘常驻进程 (Tray App)                  │
│  ┌──────────────┐   ┌──────────────────────────────────┐    │
│  │  托盘图标      │   │  配置窗口（双击/右键菜单调出）        │    │
│  │  pystray     │   │  运行开关 / 自动登录开关 / 运行实况      │    │
│  └──────┬───────┘   └──────────────────────────────────┘    │
│         │                                                   │
│  ┌──────▼──────────────────────────────────────────────┐    │
│  │                任务队列 (queue.Queue)                 │    │
│  │   同一时间只执行一个打印任务，其余排队，防止鼠标打架        │    │
│  └──────┬──────────────────────────────────────────────┘    │
│         │                                                   │
│  触发源  │                        执行引擎                    │
│  ┌──────┴───────┐   ┌───────────────────────────────────┐   │
│  │ ① DB 轮询器   │   │ 截屏 mss → OCR锚点/模板定位          │   │
│  │ ② HTTP API   │──▶│ → 状态判定（登录页?主页面?）            │   │
│  │   (FastAPI)  │   │ → SendInput 鼠标移动/点击/键盘输入     │   │
│  └──────────────┘   │ → 结果校验 → 写回 DB / 回调 / 日志     │   │
│                     └───────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

三条线程/协程各司其职：

| 组件 | 职责 | 实现 |
|------|------|------|
| 托盘 & 配置 UI | 常驻任务栏，调出配置页，启停开关 | `pystray` + Qt（Windows 用 `PyQt5`，macOS/Linux 用 `PySide6`） |
| 触发监听 | DB 轮询 / 接收 HTTP 回调，产生任务入队 | 轮询线程 + `FastAPI(uvicorn)` |
| 执行引擎 | 消费任务，截屏→识别→点击→输入→校验 | `mss` + `opencv-python` + `pynput`/`SendInput` |

启动模式：

- `./start.sh`：完整常驻模式，包含托盘、配置 UI、执行引擎、DB 轮询和 HTTP API。
- `./start.sh --ui`：无托盘完整工作模式，同样启动执行引擎、DB 轮询和 HTTP API；
  关闭配置窗口时程序退出，适合 WSLg 或没有系统托盘的环境。
- `./start.sh --headless`：无 UI 工作模式，仅运行执行引擎、DB 轮询和 HTTP API。

“目标窗口标题”用于在每个任务执行前查找标题包含指定文字的 Windows 窗口，并将其
激活、最大化，避免键盘鼠标输入落到配置窗口或其他程序。建议填写稳定且唯一的标题片段，
例如 `出货管理`，而不是会变化的完整网页标题。留空表示不主动切换窗口。该功能使用
Win32 API，因此程序运行在 WSL/Linux 进程内时不会生效；要控制 Windows 窗口，应在
Windows Python/Git Bash 环境运行程序。

## 2. 技术选型

| 环节 | 方案 | 说明 |
|------|------|------|
| 屏幕截取 | `mss` | 比 PIL/pyautogui 截屏快一个量级，支持多显示器 |
| 元素定位 | 三级策略：**OCR 文字锚点** → 多尺度模板匹配 → YOLO（预留） | 见 §2.1，专门应对用户屏幕分辨率/缩放不固定的问题 |
| OCR | `RapidOCR`（ONNX，CPU 即可） | 既做定位锚点，也读弹窗提示/打印结果 |
| 鼠标/键盘 | Win32 `SendInput`（经 `pynput`/`pywin32`） | 系统级真实事件，任何程序都认 |
| 文本注入 | `SendInput` + `KEYEVENTF_UNICODE` | 以键盘事件直接注入 Unicode 字符（自编号的字母数字与中文皆可），不经输入法、不占用剪贴板；剪贴板粘贴仅作个别程序不认注入时的后备 |
| 托盘 | `pystray` | 轻量，右键菜单 + 双击事件 |
| 配置界面 | Qt | Windows 使用兼容 Server 2016 的 `PyQt5/Qt5`，macOS/Linux 使用 `PySide6/Qt6` |
| API 触发 | `FastAPI` + `uvicorn` | 提供 `POST /print` 接口 |
| DB 触发 | 轮询待打印表（推荐）或 CDC | 见 §4 |
| DB 访问 | SQLAlchemy Core + `pyodbc` | SQL Server 主力，一套代码兼容 MySQL/PG/Oracle |
| 打包 | `PyInstaller` | 打成单个 exe，开机自启放启动项 |

运行环境要求：**Windows Server 2016、Windows 10/11**，Python 3.10+。Windows 使用
PyQt5/Qt5 兼容旧系统；macOS/Linux 使用 PySide6/Qt6。采用 OCR 锚点定位后，**不再要求
各部署机分辨率/缩放一致**（见 §2.1）。

### 2.1 元素定位：三级策略（应对"用户屏幕不固定"）

不同用户的分辨率、DPI 缩放、浏览器窗口大小都不一样，单纯模板匹配确实脆弱。
但直接上 YOLO 不是首选——它要为每个目标元素采集并标注各种分辨率/主题下的截图、
训练、且 UI 每次改版都要补数据重训；新客户环境冷启动时没有样本可用。
业务界面的按钮和输入框几乎都带文字标签，这让 OCR 锚点能"免费"获得跨分辨率能力：

| 级别 | 方法 | 适用 | 跨分辨率 | 维护成本 |
|------|------|------|---------|---------|
| **T1（默认）** | **OCR 文字锚点**：RapidOCR 检测屏幕文字，按锚点词（如"自编号""打印""登录"）取文本框位置，加偏移得到点击点 | 一切带文字的元素 | ✅ 文字检测天然尺度无关 | 改 `locators.py` 一行锚点词，零训练 |
| **T2** | **多尺度模板匹配**：0.5x~1.5x 逐档 `matchTemplate` | 无文字的图标类元素 | ⚠️ 缩放可覆盖，换主题/换肤失效 | 重截一张模板图 |
| **T3（预留）** | **YOLO 检测**（YOLO11n，CPU 可推理） | T1/T2 均不稳时的兜底 | ✅ 训练数据覆盖到就稳 | 需标注+训练+改版重训 |

- 元素定位定义**写在代码里**（`app/locators.py`，声明式结构，随 Git 版本管理），
  不进配置文件——定位是程序逻辑，不该被现场随手改动；`config.yaml` 只留运行参数
  （DB 连接、端口、开关、轮询间隔）。每个元素独立指定定位方式与参数，T1 失败自动降级尝试 T2。
- 失败快照（§6 日志）持续积累各客户环境的真实截图——**它们就是将来 T3 的训练集**。
  如果实际运行中 T1/T2 失败率确实高，再启动 M6 训练 YOLO，此时数据是现成的。
- 点击坐标全部在截屏原图坐标系计算后换算为物理屏幕坐标，天然适配任意分辨率。

#### 同名文字消歧（T1 的关键细节）

同一页面多处出现相同文字（表头有"打印"、每行操作列也有"打印"、菜单里还有一个）是
文字锚点的主要失效场景。解法是一个**逐层收窄的消歧漏斗**，每个元素按需配置其中几层：

```
OCR 全屏候选
  ① 锚词精确化：优先用长词全匹配（"打印出货单" 而非 "打印"），词越长越唯一
  ② ROI 搜索域：限定搜索区域，用屏宽/高百分比表示（如"右下 1/4"），跨分辨率仍成立
  ③ 空间关系约束：相对另一个唯一锚点定位——
     "与「车辆自编号」输入框同一行的「打印」" / "「车辆自编号」标签右侧最近的候选"
     支持 right-of / left-of / above / below / same-row + 最大距离
  ④ 多候选裁决：仍剩多个时按策略取（nearest / first / topmost），
     默认策略是 abort——记快照、报告警，宁可失败也不点错
```

定义示例（`app/locators.py`，声明式 dataclass）：

```python
VEHICLE_INPUT = TextLocator(
    anchor="自编号",
    match=Match.EXACT,               # 全匹配 / Match.CONTAINS 包含
    click_offset=(120, 0),           # 定位到标签文字，点击其右侧输入框
)

PRINT_BUTTON = TextLocator(
    anchor="打印",
    roi=(0.4, 0.3, 1.0, 0.9),        # 搜索域 (left, top, right, bottom)，屏幕百分比
    relation=Relation(ref=VEHICLE_INPUT, direction=Direction.SAME_ROW),
    pick=Pick.NEAREST,               # 约束后仍多候选时的裁决策略
    on_ambiguous=OnAmbiguous.ABORT,  # 默认：告警+快照，不误点
)

PRINT_SUCCESS = TemplateLocator(     # 无文字元素用模板（T2）
    image="templates/print_success.png",
    threshold=0.85,
)
```

两道保险：

- **配置期暴露歧义**：「测试定位」不是只显示最佳命中，而是**高亮全部候选**并标出
  最终选中的那个；发现多候选时立即警告，引导补 ROI 或关系约束——歧义在部署时解决，
  不留到运行时。
- **终极兜底**：极端情况下（无法用文字+空间关系唯一化），该元素直接改用 T2 模板——
  截图时多框进一圈周边上下文，上下文让模板天然唯一，这正是模板匹配的长处。
  T1/T2 是按元素混用的，不必全局二选一。

## 3. 核心流程（执行引擎状态机）

```
任务入队(车辆自编号)
      │
      ▼
┌─ 截屏识别当前状态 ─────────────────────────┐
│  用「登录页特征」「主页面特征」判定           │
└──────────────┬───────────────────────────┘
               │
    ┌──────────┼──────────────┐
    ▼          ▼              ▼
 登录页      主页面        都不匹配
    │          │              │
自动登录开关?   │         重试 N 次仍失败
 ┌──┴──┐      │              │
 开    关      │         任务失败，托盘气泡告警
 │     │      │         + 写日志 + 回调通知
 │  暂停任务    │
 │  提醒人工登录 │
 ▼            │
自动登录流程    │
(见 §5) ──────┤
              ▼
   ① 定位「车辆自编号输入框」(OCR锚点/模板) → 点击聚焦
   ② Ctrl+A 全选 → Delete 清空旧内容
   ③ KEYEVENTF_UNICODE 注入车辆自编号字符串
      (值来自 DB 任务记录或 API 参数，含中文、不经输入法)
   ④ (可选) OCR 回读输入框区域，校验车辆自编号已正确填入
   ⑤ 定位「打印按钮」(OCR锚点/模板) → 点击
   ⑥ (可选) 等待并识别「打印成功」特征 / 弹窗
   ⑦ 更新任务状态 → 写回 DB / HTTP 回调
```

每一步的通用骨架：`等待元素出现(超时) → 计算点击坐标 → 移动鼠标 → 点击 → 校验下一状态`。
所有"点击"都封装成 **带超时与重试的原子操作**，任何一步失败即中止本任务并告警，不盲目继续点。

### 3.1 工作流编排（流程即数据）

上面 ①~⑤ 的具体步骤不再写死在代码里，而是定义为**流程数据**（`flows.yaml`，
`app/flows.py` 数据模型），由引擎里的通用**步骤解释器**逐条执行。队列/重试/熔断/
快照等骨架与具体流程解耦：

- 动作词表刻意保持小：`点击 / 双击 / 右键 / 输入 / 等待出现 / 按键 / 等待秒数`；
  不做 if-else 与循环（防止滑向自制 RPA 平台），偶现元素用「目标未出现时跳过」覆盖。
- 输入步骤的值来源：车辆自编号（任务参数）/ 用户名 / 密码（keyring，脱敏且跳过回读）/
  图片验证码（算术题或英文字母/数字识别，§5）/ 固定文本。
- 内置流程 `print_order`（出货单打印）与 `login`（自动登录）不可删除，默认引用
  `locators.py` 注册元素；**现场在「流程编排」页重新框选任一步骤即转为本机标注定位**，
  无需发版。
- 用户在配置页「流程编排」Tab **零手写配置**地编辑流程：截屏 → 拖框选中目标 →
  下拉选动作。锚点词提取、旁侧标签借用、同名消歧 ROI、模板降级、点击点比例偏移
  全部自动推导（`flows.derive_locator`），并在标注图上真跑一次定位自检。
  每步保存标注底图（`flows_assets/`）：活文档 + 重新编辑 + 回归验证素材。

## 4. 触发源

### 4.1 数据库变动（推荐：状态表轮询）

数据访问层用 **SQLAlchemy Core** 做多数据库抽象：**SQL Server 为主力**（`pyodbc` 驱动），
同一套轮询/抢占/回写代码兼容 MySQL、PostgreSQL、Oracle、SQLite——配置里只是连接串不同，
方言差异（`TOP` vs `LIMIT`、自增列、时间函数）由 SQLAlchemy 生成。

在业务库建一张待打印任务表（或复用现有出货单表加状态字段），SQL Server 示例：

```sql
CREATE TABLE print_task (
    id          BIGINT IDENTITY(1,1) PRIMARY KEY,
    vehicle_no  NVARCHAR(32) NOT NULL,       -- 车辆自编号
    status      TINYINT DEFAULT 0,           -- 0待打印 1打印中 2成功 3失败
    retry_count INT DEFAULT 0,
    err_msg     NVARCHAR(255),
    created_at  DATETIME2 DEFAULT SYSDATETIME(),
    updated_at  DATETIME2
);
```

轮询器每 N 秒（可配置，默认 3s）执行：

1. `SELECT TOP 5 ... WHERE status=0 ORDER BY id`（其他库为 `LIMIT`，SQLAlchemy 自动处理）
2. 抢占：`UPDATE print_task SET status=1 WHERE id=? AND status=0`（防多实例重复消费）
3. 入本地队列，执行完把 2/3 与 err_msg 写回

> 为什么不用 CDC/触发器推送：本工具是单机桌面程序，轮询秒级延迟完全够用，
> 复杂度低一个数量级且天然跨数据库；打印本身就要好几秒，CDC 的毫秒级优势没有意义。

### 4.2 外部 API 调用

内置 HTTP 服务（默认 `127.0.0.1:18080`，可配置监听地址与 token）：

```
POST /print
Authorization: Bearer <token>
{ "vehicle_no": "A0231", "task_id": "外部单号(可选)", "callback_url": "结果回调(可选)" }
→ 202 { "queued": true, "queue_size": 1 }

GET /status          # 引擎状态：idle/busy/paused、队列长度、最近任务结果
GET /health          # 存活探测
```

两种触发源同时开启，统一进同一个队列串行执行。

## 5. 自动登录（带开关）

配置页提供 **「自动登录」总开关**（默认关）：

- **开关关闭**：识别到登录页时，任务挂起，托盘弹气泡「请先手动登录」，
  每 10s 重新检测，登录完成后自动继续队列。
- **开关开启**：执行内置流程 `login`（§3.1，可在「流程编排」页编辑/重新框选）
  1. 定位「用户名输入框」→ 点击 → 注入用户名
  2. 定位「密码输入框」→ 点击 → 注入密码
  3. （如有）按步骤配置识别算术或英文字母/数字验证码并填入（见下）
  4. 定位「登录按钮」→ 点击
  5. 等待「主页面特征」出现（超时 15s）；失败重试 1 次后告警
- 凭据不落明文：密码用 Windows DPAPI（`keyring` 库，凭据管理器）加密存储。
- **图片验证码**：`app/captcha.py` 统一进行自适应放大、边缘留白、散点去噪和
  多种二值化变体 OCR，并按横坐标重组被拆开的 OCR 片段。验证码步骤可选择：
  - **算术题**：识别「1+1=?」类题目，支持全角数字、常见误识别、×÷ 与
    「加减乘除」汉字算符，自动计算后输入答案；
  - **英文字母/数字**：识别 3~8 位 ASCII 字母数字组合，忽略空格和干扰符号，
    保留 OCR 识别出的大小写并原样输入。
  在「流程编排」页选择验证码类型，然后对验证码步骤**多框选一个紧贴字符的蓝框**
  即可（存相对输入框命中框的比例，跨分辨率成立）。算术模式还会生成动态算式锚点；
  两种模式都不绑定标注时的内容，验证码刷新后无需重新标注。识别失败会点击验证码
  图片刷新并最多重试 10 次，仍失败则告警转人工。该步骤默认「未出现时跳过」，
  无验证码的站点零配置兼容；复杂扭曲、滑块和点选验证码暂不支持。

## 6. 托盘与配置页面

托盘右键菜单：

```
● 运行中 / ⏸ 已暂停     ← 一键启停执行引擎
──────────────
打开配置...
立即测试打印（输入车辆自编号手动触发一单）
查看日志
──────────────
退出
```

配置页（双击托盘图标调出）分四个 Tab：

1. **基础**：运行开关、自动登录开关、DB 连接串、轮询间隔、API 监听端口与 token、失败重试次数
2. **流程编排**（§3.1）：可视化编辑工作流，用户零手写配置——
   - 「重新截屏 / 载入图片」→ 左键**拖框选中目标**（红框）→ 下拉选动作；
     右键微调点击点；验证码步骤先选择类型，再紧贴字符框选图片区域（蓝框）
   - 定位方式自动推导并展示推导说明 + 标注图自检结果；「执行此步动作」会在当前
     屏幕上真实定位并执行点击、输入、按键或等待
   - 步骤列表支持上移/下移/删除、每步单独编辑；「执行完整流程」可从第一步真实运行到
     最后一步并显示逐步结果；「保存流程」即刻生效
3. **运行实况**：**被动镜像**执行引擎——引擎每步定位后把它**真正看到、真正判定**的那一帧
   （截图 + 全部候选框）广播出来，此页实时渲染，不另开截屏器与引擎抢 OCR：
   - **实时画面**：当前流程 / 第几步 / 相位（搜索中·命中·点击输入中·超时·跳过）横幅 +
     标注截图（黄=候选 橙=约束后 绿=选中 红点=点击点）；空闲时点击「刷新目标画面」，
     配置窗口会短暂隐藏后截屏，不会把程序自己拍进实况
   - **实时日志**：右侧滚动显示引擎日志（按级别染色，无需手动刷新）；失败任务的整屏
     快照存 `logs/snapshots/`，可一键打开目录
   - **手动动作测试**：「执行选中动作」与「执行当前流程」直接调用正式步骤执行器，
     会真实点击、输入、按键和等待；执行完后显示最终屏幕。模板类元素仍可「重新截取」
     （拉框覆盖 `templates/` 下同名图，无需发版；锚点词/ROI/空间约束等逻辑变更走代码发版）
4. **登录凭据**：用户名 / 密码（DPAPI 加密存储）

运行参数持久化到 `config.yaml`；流程定义存 `flows.yaml`（流程编排页维护，用户不手编）；
内置注册元素定位在代码（`app/locators.py`），模板图片存 `templates/`，标注底图存 `flows_assets/`。

低配 CPU 的 OCR 默认使用最多 4 个线程，并关闭桌面水平文字不需要的方向分类；
可通过 `engine.ocr_threads` 和 `engine.ocr_use_angle_cls` 调整。引擎还会精确复用像素未变的
截图 OCR 结果，带 ROI 的流程步骤只识别局部区域，不放宽原有的安全消歧规则。

## 8. 关键风险与对策（纯 CV 方案必读）

| 风险 | 对策 |
|------|------|
| **用户屏幕分辨率/DPI 缩放各不相同** | T1 OCR 锚点定位天然尺度无关（§2.1）；程序声明 DPI-aware，截屏坐标→物理坐标显式换算；配置页「测试定位」在每台部署机上一键验证 |
| 目标 UI 改版/换肤 | 文字锚点通常不受影响（按钮文案没变就不用动）；图标类元素「重新截取」模板即可，无需改代码 |
| **同一文字在页面多处出现** | 消歧漏斗（§2.1）：长锚词 → ROI 搜索域 → 空间关系约束 → 多候选裁决，默认 abort 不误点；「测试定位」在配置期即暴露全部候选；无法唯一化的元素改用带上下文的 T2 模板 |
| 执行期间鼠标被外力移动 | 部署机专机专用，正常不会发生；仍保留保险丝——检测到鼠标位置与预期不符则中止本任务重试。BlockInput 锁输入不启用 |
| 浏览器窗口被遮挡/最小化 | 执行前按窗口标题把浏览器窗口置顶激活并最大化（`pywin32 SetForegroundWindow`——这是唯一一处窗口级 API，仅用于把窗口带到前台，定位输入仍是纯 CV） |
| 浏览器缩放被改动 | 部署基线锁定 100%（执行前可发 Ctrl+0 强制复位）；即便被改，T1 OCR 锚点仍尺度无关，仅影响 T2 模板元素 |
| 网页加载慢/白屏/会话过期 | 每步等待元素都带超时；超时后 F5 刷新并重试一次；会话过期会呈现为"登录页"状态，自然落入 §5 流程 |
| 输入被输入法截胡 | `SendInput` + `KEYEVENTF_UNICODE` 直注字符，绕过输入法（自编号为字母数字时天然安全，含中文亦可）；个别环境不认注入时自动降级为剪贴板粘贴（粘贴前保存、粘贴后恢复剪贴板） |
| 点了打印但没出纸 | ⑥ 步校验"打印成功"特征 + 失败整屏快照留证；连续 N 单失败自动暂停引擎并告警，避免批量空打 |
| 屏幕锁定/息屏 | 部署机设置永不锁屏息屏；或引擎检测到锁屏特征时暂停并告警 |
| 多显示器 | 配置中指定目标显示器编号，截屏与坐标换算都限定在该屏 |

## 10. 已确认的环境与决策（2026-07 确认）

1. **目标是网页**（浏览器内页面）。执行前按窗口标题激活浏览器窗口并最大化；
   页面异常（元素等待超时）时 F5 刷新重试一次。
2. **数据库需支持多种类型，主力 SQL Server**。SQLAlchemy Core 抽象，换库只改连接串（§4.1）。
3. **打印直接出纸**，无二次打印对话框。流程 ⑥ 的成功校验实现为识别页面提示/toast（若有）；
   页面无可靠反馈时，以打印按钮点击成功为任务完成标准。
4. **部署机专机专用，无人同时操作**。不启用 BlockInput 锁输入，仅保留鼠标位置保险丝（§8）。
5. **输入为车辆自编号**（通常字母数字），**全文匹配、无自动补全**，注入后无需处理联想下拉。
